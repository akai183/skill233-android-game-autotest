# 踩过的坑与判读口径

这些全部是实测踩出来的，不是推测。按「症状 → 原因 → 处置」写，遇到问题直接搜症状。

## 一、判定类

### 全屏帧差一直很大，判定「画面在动」，实际卡死

**原因**：Unity 背景常有粒子/云层/水波一直在动，全屏帧差被背景动画主导。
实测某 Loading 页全屏帧差恒为 `0.4281`，但进度条区域恒为 `0.0000`。

**处置**：**永远按区域判定**，`box` 指到真正要看的元素上（进度条、按钮、倒计时）。
用 `block_diff_map` 先看一眼差异集中在哪一行/哪一块，再定 box。

### 模板匹配分数很高但位置不对

**原因**：跨分辨率/跨设备时参考图尺寸与实机不一致，`scale` 没调。

**处置**：同分辨率采集参考图；换设备就重新采。`match_template` 返回 `(score, (x, y))`，
自匹配 score≈1.0，正常命中 0.85 以上；分数 0.9+ 但坐标偏说明 `scale` 不对。

### 数字 OCR 切不出字形（harvested=0）

**原因**：区域框太松（把相邻元素切进来）或太紧（切掉字符边缘）。
实测同一个「95%」在 `[0.43,0.842,0.16,0.02]` 能切出 3 个字形，
换成 `[0.42,0.84,0.18,0.022]` 或 `[0.41,0.838,0.2,0.026]` 都是 0 个。

**处置**：先截图，用 `block_diff_map` 或直接看图量出数字的精确包围盒，再换成屏幕比例。
`ocr_harvest` 是自举：切一次存 npz，之后 `ocr` 反复读同一位置的数字。

### 想点游戏里的按钮，uiautomator 只有 2 个节点

**原因**：Unity 用 SurfaceView 渲染，整个游戏画面在无障碍树里是 0 节点
（dump 里只有 `FrameLayout` + `View` 两层）。这是 Unity/团结引擎的固有行为，不是配置问题。

**处置**：游戏层用**坐标点击 + 截图判定**。原生层（协议弹窗、权限弹窗、系统对话框）
对象树是完整的，可以按文字点 —— 用 `wait_text` + `tap: true`。

### `wait_text` 找不到明明在屏幕上的文字

**原因**：那段文字是 Unity 画的，不在对象树里。

**处置**：同上，改用模板匹配或坐标点击。`wait_text` 只对原生控件有效。

### 中文输入不进去

**原因**：`adb shell input text` 只支持 ASCII。

**处置**：输入类操作尽量用默认账号/免登录；确实要中文就预先在设备上存好，或改走剪贴板（
部分设备 `cmd clipboard` 不可用，实测某 vivo 直接报 `No shell command implementation.`）。

## 二、日志类

### 崩溃检测返回 0 条，但日志里明明有 Exception

**原因 1**：引擎 tag 写错了。团结引擎是 **`Tuanjie`** 不是 `Unity`，且 `logcat -v epoch` 下格式是
`E Tuanjie :`（**空格**分隔，不是 `E/Unity:`）。只写 `E/Unity\s*:` 会整片漏掉。

**原因 2**：`logcat -t N` 语义不对，见下一条。

**处置**：模式要同时覆盖 `E[/ ]Unity\s*:` 和 `E[/ ]Tuanjie\s*:`；
并且**具体错误串必须排在通用兜底之前**，否则所有日志都被归到「引擎错误日志」这一大类里。

### `logcat -t N` 拿不到最近 N 行

**原因**：`-t` 的语义在部分设备/版本上是「最近 N **毫秒**」而不是「最近 N 行」。
实测某 vivo：`-t 4000` → 0 行，`-t 5000` → 1691 行，`-t 5000` 以下全是 0；
`logcat -d -t 50` 恒 0 行。游戏安静时用 `-t 500` 就返回空 → **崩溃检测静默漏报**。

**处置**：不要用 `-t`。整份 `logcat -d -v epoch` 拉下来（实测约 7.7MB / 500ms）后本地截断。
判定崩溃必须看全窗口，不能截断，否则最早的崩溃会被切掉。

### 崩溃事件数量翻倍

**原因**：`check_crash` 步骤扫一次、跑测收尾又扫一次，同类事件被追加两次。

**处置**：按 `kind` 合并累加 `count`、保留首条样本（工具包已实现 `_merge_crashes`）。

### 崩溃样本刷屏，一次打印上千行

**原因**：通用兜底模式（`E[/ ]Tuanjie\s*:`）会命中每条引擎日志，包括空白续行和栈行。

**处置**：结果按 `kind` 聚合，每类只留首条 + `count`。**调试时不要全量 print 扫描结果**，
先按类统计，需要细节再去 `crash-logcat.log` 里 grep。

### 日志里大量 `NotSupportNative2Managed` / `NotSupportAdjustorThunk`

**含义**：IL2CPP 不支持 native→managed 转换 / adjustor thunk。这几乎总是
**首包 AOT 代码与热更 DLL 版本不匹配**（包体构建时间早于 CDN 上热更包的时间）。

**处置**：核对 `assets/build_info` 的构建时间与 CDN 热更版本时间；换一个与热更同批构建的包。
这不是 adb 链路问题，重装/重启都不解决。

## 三、设备与链路类

### `screencap` 偶发卡死 60 秒，之后又正常

**原因**：USB 传输层偶发卡死，尤其在经过 Hub（尤其是无独立供电的 Hub）或 USB 2.0 链路上。
实测同一台设备 20 次循环全部正常（0.50–0.97s），但会突然卡一次 60s。

**处置**：截图用**短超时**（15–20s）而不是默认 60s，避免一次抖动拖死整个流程；
临时失败退避重试 → 连续 3 次失败触发 `adb reconnect` 再试一次 → 仍失败才判设备掉线。
物理层：直连机器、换带独立供电的 Hub、换能传数据的线。

### `grep` 没匹配到就被当成设备故障

**原因**：`adb shell` 的退出码是远端命令的退出码，`grep` 无匹配返回 1，
`settings get` 缺键、某些 `dumpsys` 子命令也返回非 0。

**处置**：`shell()` 默认 `check=False`（不因退出码抛错），只有**传输层**故障
（`device offline` / `no devices` / `device not found`）才抛 `DeviceGone`。

### `am start -n` 报 Error type 3

**原因**：activity 未导出。

**处置**：用 `monkey -p <包名> -c android.intent.category.LAUNCHER 1`，这是最稳的启动方式。
`launch` action 在不传 `activity` 时就是走这条路。

### 设备连着但 `adb devices` 是空的

按顺序查：

1. 手机上有没有「允许 USB 调试」授权弹窗（拔插会重新弹）
2. `adb kill-server; adb start-server` 后重看
3. 换线、换口、直连不用 Hub（**最常见**）
4. macOS 上还可以看内核有没有枚举到设备：`log show --predicate 'process == "kernel"' --last 2m | grep -i usb`

### 装 45MB 的包要 1.5 分钟

USB 2.0 Hub 链路上的正常速度，不是卡死。别中途 Ctrl-C。

## 四、流程编排类

### 参数名写错了，流程照跑但没生效

**原因**：`runner` 不校验未知参数（只校验未知 action）。

**处置**：新增/修改流程后**必先 `--dry-run`**，再真跑。参数表见 [flow-schema.md](flow-schema.md)。

### 第一步就失败，后面全跳过

检查是不是标了 `"fatal": true`。默认所有步骤都会跑完、失败收集起来一次性出报告；
只有 fatal 才中断。要「一次发现多个问题」就别随便加 fatal。

### 想「记录但不判失败」

`check_crash` 设 `must_clean: false` —— 崩溃照样进报告和 `crash_events`，但该步骤判 pass。
`wait_template` / `wait_text` 同理用 `must_find: false`。

### 截图全黑 / 全透明

设备息屏了。`doctor` 的「屏幕唤醒」项会报出来；流程开头加 `wake` 步骤，
并确认 `stay_on_while_plugged_in` 已开。

### 自检里截图类、模板匹配、Activity 用例假失败

**症状**：`selftest.py` 报「模板匹配自匹配得分 -1.000」、「Activity 格式异常 ''」，
但同时 `shell`、`截图字节数` 这些用例都是通过的。

**原因**：设备处于息屏 / 锁屏状态。息屏时截图出来是纯色（方差为 0，NCC 无定义 → 返回 -1），
没有前台 Activity（返回空串），模板匹配自然也就没有纹理可比。这是**环境状态问题，不是代码坏了**。

**处置**：`selftest.py` 现在会先 `wake()` 一次；纯色画面下模板匹配用例改为「跳过」而不是判失败。
仍然报 Activity 为空，就手动解锁（有 PIN 的话自检不解锁，避免动别人的锁屏）。
真跑流程时流程开头的 `wake` + `unlock` 步骤会处理这件事。

### 关面板必然超时，试遍所有策略都没反应

**症状**：`close_panel` 跑满 timeout（25s），报告里「尝试 9 次，策略 [红X色块, 右上X坐标, ...]」，
但手动点同样的坐标一次就关掉了。

**原因**：策略函数里引用了一个从未赋值的变量，`NameError` 被 `except Exception: pass` 吞掉，
于是**所有策略实际上一次都没执行**，只是在空转等待。

**教训**：凡是「点了但完全没效果」且所有候选都无效时，先怀疑**异常被静默吞掉**。
排查方法：临时把 `except Exception: pass` 改成 `except Exception as e: print(e)`，
或给每个策略记录执行结果（工具包现在会记 `红X色块(未找到控件)` / `右上X坐标(失败:NameError)`）。
**永远不要用裸 `except: pass` 包住有副作用的动作。**

### 面板打开了但报告说"没打开"/"已关闭"

**症状**：截图明明是面板，`assert_gone` 报「主城模板仍然在画面上」；或反之。

**原因 1**：画面带背景动画，模板得分抖动。实测同一画面 12 帧得分 0.858–0.963，3 帧低于 0.90。
**处置**：判定类动作连拍 N 帧取最大值（`samples` 参数，默认 3），不要只看一帧。

**原因 2**：`assert_gone` 的 `box` 没给，全图搜索被别处相似元素干扰。
**处置**：把 `box` 限定到目标元素所在区域。

### 引导浮层拦截所有点击，但查的时候它还没出现

**症状**：进主城后立刻 `tap_color red` 查红 X，查不到（`must_find: false` 静默跳过）；
随后所有入口点击全部无效，但 `close_panel` 又因「一开始就匹配主城」判成功 → 整条流程假绿。

**原因**：新手引导浮层在主城加载完后 **1~2 秒才弹**，是延迟出现的。

**处置**：用 `dismiss_tutorial`（轮询等待出现 → 点掉 → 再确认没重弹），
不要用一次性的 `tap_color`。这个动作会一直轮询到 `timeout`，查不到才算真的没有。

### `screencap` 返回 0 字节或截断帧

**症状**：`vision.FrameError: raw 帧太短：0 字节`，或 `raw 帧不完整：需要 10402576，实际 7520912`。

**原因**：USB 链路抖动。内核日志会有 `AppleUSBXHCIRequest ... babble error: 0 bytes transferred`。
**注意截断帧**：长度不是 0 但也不够 `16 + w*h*4`，只校验 `len > 16` 会漏过去，
解码出一张撕裂的图，后续模板匹配全乱。

**处置**：`screencap_raw` 已按 `w`/`h` 算出**完整帧应有的字节数**再校验，
不符则退避重试（默认 4 次），全失败才抛错并提示查线/换直连 USB 口。
物理层解决：换能传数据的线、直连机器不用 Hub、或用带独立供电的 Hub。

### 设备突然从 adb 消失，但 USB 还插着

**症状**：`DeviceGone: 没有在线设备`，`ioreg` 里还能看到设备，内核日志刷 `babble error`。

**处置**：`adb kill-server` / `adb reconnect offline` 都**无效**；
等 60 秒左右设备会自行重新枚举成功（`transport_id` 会变）。
这期间不要反复重试刷命令，等它回来即可。根治靠换线/直连。

## 五、口径

- **`crashed` 与 `passed` 分开看**：步骤全 pass 但 `crashed: true` 是常态（流程走通了，期间崩了）。
- **崩溃归类是线索不是结论**：定性要看日志上下文 + 截图，工具只负责把噪音压成类别 + 次数。
- **不自动改基准图**：视觉断言失败先人工确认是「功能坏了」还是「美术改版了」。
- **结论必须可复现**：记下包体 `versionName`、构建时间、以及本次的 `flow.json`。
